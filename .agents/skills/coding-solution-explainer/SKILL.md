# 코딩 문제 풀이 해석 작성

현재 문제 폴더의 `문제.js`를 읽고 같은 폴더의 `설명.md`에 풀이를 정리한다. 문제 폴더를 특정하지 않았다면 대화에서 가장 최근에 다룬 문제 폴더를 사용한다.

## 작성 전 확인

- `문제.js` 전체를 읽어 사용자의 실제 접근 방식과 코드 흐름을 파악한다.
- `문제.md`가 있으면 문제 조건과 입출력 예를 확인한다.
- 가능한 경우 기존 예제로 코드를 실행한다. 풀이에 오류나 반례가 있으면 정답처럼 설명하지 말고 오류가 발생하는 조건과 수정 방향을 알린다.
- `문제.js`와 `문제.md`는 수정하지 않는다.

## `설명.md` 작성

다음 구조를 기본으로 사용하되, 내용이 없는 섹션은 만들지 않는다.

```md
# 내 풀이

## 접근
## 풀이 과정
## 복잡도
```

- 정렬, 해시, 스택처럼 풀이의 핵심 아이디어를 먼저 설명한다.
- 왜 이 방법이 성립하는지 구체적인 입력 예와 함께 설명한다.
- 풀이 과정은 실제 코드가 실행되는 순서대로 작성한다.
- 사용자의 풀이 코드를 코드 블록으로 포함한다. 파일 끝의 테스트용 `console.log(...)`는 제외한다.
- 시간 복잡도와 공간 복잡도를 입력 크기 변수와 함께 정확히 작성한다.
- 불필요한 반복이나 더 간단한 반환 방식처럼 실제 도움이 되는 개선점이 있으면 짧게 덧붙인다. 사용자가 요청하지 않은 대체 풀이를 새로 만들지는 않는다.
- 기존 `설명.md`에 사용자가 작성한 관련 없는 내용이 있으면 보존하고, 요청한 섹션만 추가하거나 갱신한다.

## 다른 사람의 풀이

사용자가 다른 사람의 풀이 코드를 함께 전달한 경우에만 내 풀이 아래에 다음 내용을 추가한다.

```md
# 다른 사람의 풀이

<전달받은 코드>

## 코드 해석
## 내 풀이와의 차이
## 한 줄로 정리
```

- 코드가 사용하는 메서드, 연산자, 콜백의 반환값을 실제 평가 순서대로 설명한다.
- 조기 종료, 원본 배열 변경, 사용하지 않는 매개변수처럼 동작을 이해하는 데 중요한 점을 짚는다.
- 내 풀이와 핵심 아이디어가 같다면 같다고 명시하고, 표현 방식이나 실행 흐름의 차이만 설명한다.
- 다른 사람의 풀이가 전달되지 않았다면 이 섹션을 만들거나 요청하지 않는다.

## 문체

- 코딩 테스트를 학습 중인 독자가 이해할 수 있는 자연스러운 한국어로 쓴다.
- 한 문장에는 한 가지 내용만 담고, 코드에서 확인할 수 없는 의도는 추측하지 않는다.
- 메서드 이름과 변수명은 인라인 코드로 표시한다.

## 완료 확인

작성 후 `설명.md`가 존재하는지 확인하고, 실행한 예제의 결과와 생성한 파일 경로를 간단히 안내한다.
