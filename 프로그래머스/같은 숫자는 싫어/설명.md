# 내 풀이

```js
function solution(arr) {
    var answer = [];
    for (const el of arr) {
        if (answer[answer.length - 1] === el) continue;
        answer.push(el);
    }
    return answer;
}
```

## 접근

결과 배열 `answer`의 마지막 값과 현재 원소 `el`을 비교합니다. 두 값이 같으면 현재 원소는 바로 앞의 연속 중복이므로 건너뛰고, 다르면 `answer`에 추가합니다.

예를 들어 `[1, 1, 3, 3, 0, 1, 1]`을 순회할 때 첫 번째 `1`만 `answer`에 넣습니다. 다음 `1`은 `answer`의 마지막 값과 같아서 건너뜁니다. 이 과정을 반복하면 `[1, 3, 0, 1]`이 남습니다.

## 풀이 과정

1. 빈 배열 `answer`를 만듭니다.
2. `for...of`로 `arr`의 원소를 앞에서부터 하나씩 꺼냅니다.
3. `answer[answer.length - 1]`이 현재 원소와 같으면 `continue`로 다음 원소를 확인합니다.
4. 다르면 현재 원소를 `answer`에 `push`합니다.
5. 순회가 끝나면 `answer`를 반환합니다.

## 복잡도

입력 배열의 길이를 `n`, 결과 배열의 길이를 `k`라고 하면 시간 복잡도는 모든 원소를 한 번 확인하므로 `O(n)`입니다. 결과 배열에 최대 `k`개를 저장하므로 공간 복잡도는 `O(k)`이며, 최악의 경우 `O(n)`입니다.

# 다른 사람의 풀이

```js
function solution(arr) {
    return arr.filter((val, index) => val != arr[index + 1]);
}
```

## 코드 해석

`filter`는 각 원소의 `val`과 인덱스 `index`를 콜백에 전달하고, 콜백이 `true`를 반환한 원소만 새 배열에 담습니다.

`arr[index + 1]`은 현재 원소의 다음 원소입니다. 다음 원소와 같으면 `false`가 되어 현재 원소를 제거하고, 다르면 `true`가 되어 남깁니다. 따라서 같은 값이 연속된 구간에서는 마지막 값만 남습니다. 마지막 원소는 다음 원소가 `undefined`이므로 항상 남습니다.

문제의 원소는 모두 숫자이므로 `!=`도 올바르게 동작합니다. 다만 같은 타입의 값만 비교하는 문제에서는 `!==`가 의도를 더 명확하게 보여 줍니다.

## 내 풀이와의 차이

내 풀이는 결과 배열의 마지막 값과 비교해 연속 구간의 첫 값을 남깁니다. 다른 사람의 풀이는 다음 원소와 비교해 연속 구간의 마지막 값을 남깁니다. 같은 값으로 이루어진 구간에서는 첫 값과 마지막 값이 같으므로 반환 결과는 같습니다.

두 코드 모두 원본 배열 `arr`을 변경하지 않고, 한 번의 순회로 결과 배열을 만듭니다. 시간 복잡도는 둘 다 `O(n)`이고, 결과 배열 크기를 `k`라고 할 때 공간 복잡도도 둘 다 `O(k)`이며 최악의 경우 `O(n)`입니다. 다른 사람의 풀이는 `filter`를 사용해 더 짧게 표현했고, 내 풀이는 어떤 값을 건너뛰고 추가하는지 실행 흐름이 더 직접적으로 드러납니다.

## 한 줄로 정리

두 풀이는 복잡도가 같고, 내 풀이는 이전 결과와 비교해 첫 값을 남기며 다른 사람의 풀이는 다음 값과 비교해 마지막 값을 남깁니다.
