# 내 풀이

```javascript
function solution(genres, plays) {
    const obj = genres.reduce((total, cur, index) => { 
        return { ...total, 
            [cur] : {
                key: cur,
                value: [...(total?.[cur]?.value || []), `${plays[index]}-${index}`],
                sum: (total?.[cur]?.sum || 0) + plays[index]
            }
        }
    }, {});
    for (const el in obj) {
        obj[el].value.sort((a, b) => {
            const [playA, indexA] = a.split('-');
            const [playB, indexB] = b.split('-');
            if (playA === playB) indexA - indexB;
            return playB - playA;
        });
    }

    return Object.values(obj).sort((a, b) => b.sum - a.sum).map(({ value }) => {
        return value.slice(0, 2).map((item) => Number(item.split('-')[1]));
    }).flat();
}
```

## 접근

장르별로 노래 목록과 총 재생 수를 함께 모은 뒤, 각 장르 안의 노래를 정렬합니다. 이후 장르를 총 재생 수 내림차순으로 정렬하고, 각 장르에서 앞의 두 곡만 꺼냅니다.

## 풀이 과정

1. `reduce`로 장르별 객체를 만듭니다. `sum`에는 해당 장르의 총 재생 수를, `value`에는 `재생수-고유번호` 문자열을 저장합니다.
2. 각 장르의 `value`를 재생 수 내림차순으로 정렬합니다.
3. 장르 객체들을 `sum` 내림차순으로 정렬합니다.
4. 각 장르에서 `slice(0, 2)`로 최대 두 곡을 고르고, 문자열에서 고유 번호만 분리해 하나의 배열로 펼칩니다.

예제에서 `pop`의 `sum`은 3,100이고 `classic`의 `sum`은 1,450입니다. 따라서 `pop`을 먼저 처리하고, 각각의 장르 안에서 재생 수가 큰 두 곡을 선택합니다.

## 확인할 점

동률일 때 고유 번호가 낮은 곡을 먼저 두려는 코드가 있습니다. 하지만 아래 줄은 값을 계산만 하고 반환하지 않습니다.

```javascript
if (playA === playB) indexA - indexB;
```

따라서 동률이면 비교 함수는 결국 `0`을 반환합니다. 현재 JavaScript의 안정 정렬에서는 입력 순서가 유지되어 우연히 낮은 고유 번호가 앞에 남지만, 조건을 코드로 명시하려면 이 식 앞에 `return`이 필요합니다.

## 복잡도

`value` 배열과 장르 객체를 매번 전개 연산자(`...`)로 새로 복사하므로, 한 장르에 노래가 많이 몰리면 `reduce` 단계가 최악 `O(n²)`입니다. 그 뒤 정렬은 전체적으로 `O(n log n)`입니다. 공간 복잡도는 장르별 노래 정보를 저장하므로 `O(n)`입니다.

# 다른 사람의 풀이

```javascript
function solution(genres, plays) {
    var dic = {};
    genres.forEach((t,i)=> {
        dic[t] = dic[t] ?  dic[t] + plays[i] :plays[i];        
    });

    var dupDic = {};
    return genres          
          .map((t,i)=> ({genre : t, count:plays[i] , index:i}))
          .sort((a,b)=>{               
               if(a.genre !== b.genre) return dic[b.genre] - dic[a.genre];
               if(a.count !== b.count) return b.count - a.count;
               return a.index - b.index;
           })
           .filter(t=>  {
               if(dupDic[t.genre] >= 2) return false;
               dupDic[t.genre] = dupDic[t.genre] ? dupDic[t.genre]+ 1 : 1;
               return true;
            })
           .map(t=> t.index);    
}
```

## 코드 해석

1. `dic`에 장르별 총 재생 수를 계산합니다.
2. 모든 노래를 `{ genre, count, index }` 객체로 바꿉니다.
3. 한 번의 `sort`에서 장르 총 재생 수, 노래 재생 수, 고유 번호 순으로 비교합니다. 즉, 최종 앨범 순서가 배열 전체에 바로 만들어집니다.
4. `filter`의 `dupDic`은 장르별로 이미 통과한 곡 수를 셉니다. 두 곡을 통과시킨 장르는 이후 곡을 버립니다.
5. 남은 객체에서 `index`만 꺼내 반환합니다.

## 내 풀이와의 차이

둘 다 장르 총 재생 수와 장르 안의 노래 순서를 이용한다는 핵심은 같습니다. 내 풀이는 장르별로 먼저 묶고 정렬한 뒤 펼치고, 다른 풀이는 모든 노래를 한 배열에 두고 최종 우선순위로 한 번 정렬합니다.

다른 풀이는 동률의 고유 번호 비교를 `return a.index - b.index`로 명시합니다. 또한 배열과 객체를 매 반복마다 복사하지 않으므로 시간 복잡도는 정렬이 지배하는 `O(n log n)`입니다. 내 풀이는 장르 구조를 따라가 읽기 쉽지만, 문자열을 만들고 다시 `split`하는 과정과 전개 복사가 추가됩니다.

## 한 줄로 정리

다른 풀이는 모든 노래를 최종 순서대로 정렬한 뒤 장르별 두 곡만 남기는, 더 짧고 `O(n log n)`인 방식입니다.
