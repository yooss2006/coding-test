# 내 풀이

## 접근

큐의 맨 앞 프로세스가 현재 남은 프로세스 중 가장 높은 우선순위인지 확인하는 방식입니다. `list`에는 우선순위와 원래 위치를 `"우선순위-인덱스"` 문자열로 함께 저장합니다. 따라서 같은 우선순위가 여러 개여도 목표 프로세스를 원래 인덱스로 구분할 수 있습니다.

`max`에는 현재 실행할 수 있는 가장 높은 우선순위를 저장합니다. 맨 앞의 우선순위가 `max`보다 낮으면 다시 큐 뒤로 보내고, 같으면 실행 순서인 `count`를 증가시킵니다.

예를 들어 `[2, 1, 3, 2]`, `location = 2`에서는 `max`가 `3`입니다. 앞의 `2`, `1`은 뒤로 이동하고, 인덱스 `2`의 `3`이 처음 실행되므로 `1`을 반환합니다.

```text
[2-0, 1-1, 3-2, 2-3]  -- 2, 1을 뒤로 이동 -->  [3-2, 2-3, 2-0, 1-1]
                                                            |
                                                        3-2 실행
                                                            |
                                                       count = 1
```

## 풀이 과정

```js
function solution(priorities, location) {
   let max = Math.max(...priorities);
   let list = priorities.map((item, index) => `${item}-${index}`);
   let count = 0;
    while (list.length > 0) {
        const item = list.shift();
        const value = Number(item.split('-')[0]);
        const index = Number(item.split('-')[1]);
        if (max !== value) {
            list.push(item);
        } else if(location === index) {
            count++;
            break;
        } else {
            count++;
            max = Math.max(...list.map((item) => Number(item.split('-')[0])))
        }
    }

    return count;
}
```

1. `Math.max(...priorities)`로 전체 큐의 최대 우선순위를 구합니다.
2. `map`으로 각 우선순위에 원래 위치를 붙여 `list`를 만듭니다.
3. `shift()`로 맨 앞 항목을 꺼내 우선순위와 인덱스를 분리합니다.
4. 우선순위가 `max`보다 낮으면 아직 더 높은 프로세스가 있으므로 `push()`로 다시 뒤에 넣습니다.
5. 우선순위가 `max`이면 실행합니다. 목표 인덱스라면 종료하고, 아니면 실행 횟수를 증가시킨 뒤 남은 큐의 최대 우선순위를 다시 구합니다.

## 복잡도

- 시간 복잡도: `O(n²)`
  - `shift()`는 배열의 앞 요소를 제거하며 나머지 요소를 당겨야 하고, 실행할 때마다 `map()`과 `Math.max()`로 남은 큐를 다시 순회합니다.
- 공간 복잡도: `O(n)`
  - 우선순위와 인덱스를 저장한 `list`를 추가로 만듭니다.


# 다른 사람의 풀이

## 풀이 1

```js
function solution(priorities, location) {
    var list = priorities.map((t, i) => ({
        my: i === location,
        val: t
    }));
    var count = 0;

    while (true) {
        var cur = list.splice(0, 1)[0];
        if (list.some(t => t.val > cur.val)) {
            list.push(cur);
        } else {
            count++;
            if (cur.my) return count;
        }
    }
}
```

### 코드 해석

- `map()`은 각 프로세스를 `{ my, val }` 객체로 바꿉니다. `my`는 현재 프로세스가 목표 위치인지 나타내는 불리언이고, `val`은 우선순위입니다.
- `splice(0, 1)[0]`은 맨 앞 프로세스 하나를 큐에서 꺼냅니다.
- `some(t => t.val > cur.val)`은 남은 큐를 앞에서부터 확인하다가 현재 프로세스보다 높은 우선순위를 찾으면 즉시 `true`를 반환합니다.
- 더 높은 우선순위가 있으면 `push(cur)`로 현재 프로세스를 뒤로 보냅니다. 없으면 실행한 것이므로 `count`를 증가시키고, `cur.my`가 `true`일 때 바로 실행 순서를 반환합니다.

### 내 풀이와의 차이

두 풀이 모두 맨 앞 프로세스를 꺼낸 뒤 더 높은 우선순위가 있는지 확인하는 큐 시뮬레이션입니다. 내 풀이는 `max`를 따로 관리하지만, 이 풀이는 매 반복마다 `some()`으로 현재 프로세스보다 높은 값이 있는지 직접 찾습니다. 또 문자열을 분리하는 대신 객체의 `my` 속성으로 목표 프로세스를 표시해 읽기가 더 직관적입니다.

### 한 줄로 정리

목표 여부를 객체에 미리 표시하고, `some()`으로 더 높은 우선순위의 존재를 확인하는 큐 시뮬레이션입니다.

## 풀이 2

```js
function solution(priorities, location) {
    var arr = priorities.map((priority, index) => {
        return {
            index: index, priority: priority
        };
    });

    var queue = [];

    while (arr.length > 0) {
        var firstEle = arr.shift();
        var hasHighPriority = arr.some(ele => ele.priority > firstEle.priority);
        if (hasHighPriority) {
            arr.push(firstEle);
        } else {
            queue.push(firstEle);
        }
    }

    return queue.findIndex(queueEle => queueEle.index === location) + 1;
}
```

### 코드 해석

- `arr`에는 `{ index, priority }` 형태로 원래 위치와 우선순위를 저장합니다.
- 매 반복에서 `shift()`로 맨 앞 프로세스를 꺼내고, `some()`으로 더 높은 우선순위가 남았는지 확인합니다.
- 더 높은 프로세스가 있으면 다시 `arr`의 뒤로 보내고, 없으면 실행 순서를 담는 `queue`에 추가합니다.
- 큐가 완전히 빌 때까지 모든 프로세스의 실행 순서를 만든 뒤, `findIndex()`로 `location`과 일치하는 프로세스의 위치를 찾아 `1`을 더해 반환합니다.

### 내 풀이와의 차이

내 풀이는 목표 프로세스가 실행되는 순간 반복을 끝냅니다. 반면 이 풀이는 모든 프로세스를 실행 순서대로 `queue`에 저장한 다음 목표의 위치를 찾습니다. 따라서 목표가 앞쪽에 실행돼도 끝까지 시뮬레이션하지만, 실행 순서 전체를 확인할 수 있다는 장점이 있습니다. 또한 이 풀이도 `shift()`와 `some()`을 사용하므로 시간 복잡도는 내 풀이처럼 `O(n²)`이고, `arr`와 `queue`를 모두 저장해 공간 복잡도는 `O(n)`입니다.

### 한 줄로 정리

전체 실행 순서를 먼저 배열로 만든 뒤 목표 프로세스의 순번을 찾는 큐 시뮬레이션입니다.
